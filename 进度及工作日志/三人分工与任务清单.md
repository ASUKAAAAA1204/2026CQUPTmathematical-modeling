# 三人分工与任务清单

## 1. 总目标

三人并行推进并最终合成为一套可提交、可复现、可答辩的竞赛成果，覆盖以下四层：

1. 建模层：四问统一口径、统计检验、动态阈值、判定规则。
2. 代码层：数据读取、建模、交叉验证、bootstrap、Excel、图表生成。
3. 论文层：正文写作、表格嵌入、图表说明、创新点与边界声明。
4. 协同层：版本统一、接口明确、结果同步、答辩口径一致。

总原则：

- 不再继续拔高概念包装。
- 以题面四问完成度为第一优先级。
- 以“文档、公式、程序一致”为底线。
- 以“可复现、可答辩、可交付”为验收标准。

---

## 2. 三人角色定义

### A：建模负责人

A 负责“模型是否正确、是否偏题、是否能答辩”。

核心职责：

- 锁定整篇论文的统一数学口径。
- 设计问题 1-4 的模型表达与统计解释。
- 审核问题 2 的主效应、交互效应、显著性与效应量口径。
- 审核问题 3 的动态阈值定义是否完全回到题目要求。
- 审核问题 4 的三区域规则、灰区规则与 bootstrap 解释是否稳妥。
- 负责最终创新点与边界声明不过度、不失真。

### B：代码与实验负责人

B 负责“结果能不能跑出来、能不能复现、数值是否一致”。

核心职责：

- 负责数据清洗、建模、交叉验证、bootstrap、图表与 Excel 附件输出。
- 负责问题 1 的预测表、问题 2 的统计结果表、问题 3 的动态阈值表、问题 4 的区间图。
- 负责保证所有结果都能通过脚本重复生成。
- 负责结果文件命名、存放路径、版本管理。

### C：论文与答辩负责人

C 负责“论文能不能交、语言是否稳妥、答辩口径是否统一”。

核心职责：

- 负责正文写作、图表嵌入、结果解释、摘要、结论、创新点与局限性表述。
- 负责把数学结果翻译成评审可接受的表述。
- 负责答辩提纲、答辩图示和口头表达口径。
- 负责通篇查重式检查：术语是否统一、前后是否矛盾、结论是否越界。

## 4. 建模层细化分工

## 4.1 统一模型口径

### A 具体做什么

- 写出最终主模型公式。
- 决定问题 1-4 是否共用同一衰减函数。
- 明确哪些符号在全文固定不变。
- 审核是否出现“文档一套、代码一套、答辩一套”的口径分裂。

### B 具体做什么

- 按 A 确认的主模型实现代码。
- 建立参数输入、数据输出、结果缓存接口。
- 将模型公式映射为可运行脚本。

### C 具体做什么

- 把主模型公式写成论文可读版本。
- 保证主模型在摘要、正文、结论、答辩稿中表述一致。

---

## 4.2 问题 1：初值验证与 23-29 天预测

### A 具体做什么

- 决定个体层和类型层初值的定义。
- 明确初值相关性检验的数学表达。
- 明确共享平均衰减函数与独立拟合的比较方法。
- 审核 23-29 天预测必须来自统一模型，禁止插值替代。

### B 具体做什么

- 提取第 0 天数据。
- 计算均值、标准差、95% 置信区间。
- 计算 `corr(M0, M90/M0)`。
- 跑“共享平均衰减函数 vs 单样品独立拟合”的 AIC/BIC 或检验表。
- 输出 23-29 天预测表。

### C 具体做什么

- 写问题 1 的结果解释。
- 写“初值与衰减可近似分离”的稳妥表述。
- 写共享平均函数合理性的结论。
- 整理问题 1 表格进入论文。

---

## 4.3 问题 2：独立贡献与交互效应分析

### A 具体做什么

- 设计问题 2 的标准统计模型。
- 确定主效应、交互效应、时间 × 锈蚀项必须出现。
- 决定问题 2 主文必须给出的统计量：
  - 系数
  - 标准误
  - t/z 值
  - p 值
  - 效应量
- 决定门槛型交互只能作为补充创新，不可替代主统计归因。

### B 具体做什么

- 实现问题 2 的回归/分层回归/混合效应模型。
- 输出问题 2 的统计结果表。
- 做三种交互构造的消融实验：
  - 无交互
  - 对称交互
  - 门槛交互
- 输出误差对比图和锈蚀钢筋误差改善比例。

### C 具体做什么

- 先写标准统计归因。
- 再写门槛交互的工程意义。
- 避免把问题 2 写偏成纯预测比赛。
- 把“统计关联”与“工程解释”区分清楚。

---

## 4.4 问题 3：动态阈值修正表

### A 具体做什么

- 明确问题 3 主体任务是 `1-90` 天动态阈值表。
- 锁定公式

\[
\Theta_s(t)=\Theta_s^{GB}\cdot R_s(t)
\]

- 决定“反推初值”只作为补充解释，不能替代动态阈值表。

### B 具体做什么

- 生成 `1-90` 天动态阈值 Excel。
- 计算四类样品的 `R_s(t)`、`Θ_s(t)`、类型均值预测剩磁。
- 校验 Excel 数值与正文公式一致。
- 输出可直接提交的附件版本。

### C 具体做什么

- 写问题 3 正文。
- 写“国标静态阈值映射到观测时点”的解释。
- 写 Excel 附件说明。
- 确保正文没有“回避问题3表格输出”的嫌疑。

---

## 4.5 问题 4：判定流程与置信度评估

### A 具体做什么

- 锁定问题 4 的四步结构：
  - 数据预处理
  - 衰减预测
  - 动态阈值调整
  - 结果置信度评估
- 定义三区域规则。
- 定义灰区条件和长延迟失效条件。
- 审核 bootstrap 解释是否严谨。

### B 具体做什么

- 实现异常值检测、缺失值填补、单位核验、类型检查。
- 跑 cluster block bootstrap。
- 生成区间估计。
- 生成反推初值区间宽度—延迟天数曲线。
- 准备现场流程图所需数据。

### C 具体做什么

- 写问题 4 正文。
- 写三区域判定解释。
- 写灰区和复检建议。
- 把工程流程写成评审容易接受的形式。

## 9. 协同接口分工

这一层最容易被忽略，但决定最终是否顺畅。

## 9.1 A 对 B 的接口

A 必须给 B 明确的内容：

- 主模型公式最终版
- 问题 2 统计模型最终版
- 问题 3 阈值公式最终版
- 问题 4 判定规则最终版

不能给“模糊方向”，必须给可编码公式。

## 9.2 B 对 C 的接口

B 必须给 C 明确的内容：

- 表格最终版
- 图表最终版
- 每个数字的来源
- 每个结果的简短解释

不能只给原始输出。

## 9.3 C 对 A/B 的接口

C 必须反向提出：

- 哪些表述太强，需降级
- 哪些图表不够支撑正文
- 哪些结论缺数字或缺检验

不能等写完才发现逻辑缺口。

## 11. 禁止事项

三人协作中禁止出现以下情况：

1. A 临时改公式但不通知 B 和 C
2. B 改代码口径但不回传 A 和 C
3. C 擅自改数学定义以追求文风
4. 问题 2 被写成纯预测比较而没有统计归因
5. 问题 3 没有 `1-90` 天动态阈值表
6. 问题 4 没有 bootstrap 区间和三区域规则
7. 图表数字与正文不一致

---

## 12. 最终协作原则

最终三人协作必须形成如下分工闭环：

- A 盯住“是否偏题、是否严谨”
- B 盯住“是否可跑、是否可复现”
- C 盯住“是否可交、是否可答辩”

最终目标不是做一个概念最炫的方案，而是做一个：

> 完成度高、统计规范、工程清楚、图表充分、论文成熟、答辩稳定的竞赛建模成稿
