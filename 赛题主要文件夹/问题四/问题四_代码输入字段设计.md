# 问题四代码输入字段设计

## 1. 设计目标

问题四后续如果要从“赛题内实验数据”扩展到“真实现场判定”，代码侧必须先有稳定的输入字段标准。  
本文件定义问题四的数据输入接口，目的是让：

- 建模口径不歧义
- 代码字段可直接实现
- 论文描述、Excel 表格、脚本参数三者一致

---

## 2. 输入对象拆分

问题四建议拆成 4 个输入对象：

1. `case_info`：案件与时间信息
2. `sample_info`：样品与测量信息
3. `weather_series`：逐日天气轨迹
4. `config`：判定参数与稳健性设置

---

## 3. case_info 字段

| 字段名 | 类型 | 是否必填 | 含义 | 校验规则 |
|---|---|---|---|---|
| `case_id` | string | 是 | 案件编号 | 不能为空 |
| `lightning_date` | string/date | 是 | 疑似雷击日期 | 必须可解析为日期 |
| `measurement_date` | string/date | 是 | 剩磁测量日期 | 不得早于雷击日期 |
| `sampling_date` | string/date | 否 | 实际取样日期 | 若缺失可默认等于测量日期 |
| `site_name` | string | 否 | 工程/地点名称 | 建议填写 |
| `site_lon` | float | 否 | 经度 | 合法经纬度 |
| `site_lat` | float | 否 | 纬度 | 合法经纬度 |
| `weather_source` | string | 否 | 天气数据来源 | 如气象站/再分析产品 |

推荐派生字段：

- `delay_days = measurement_date - lightning_date`

---

## 4. sample_info 字段

| 字段名 | 类型 | 是否必填 | 含义 | 校验规则 |
|---|---|---|---|---|
| `sample_id` | string/int | 是 | 样品编号 | 同一案件内唯一 |
| `sample_type` | string | 是 | 样品类型 | 必须在四类集合内 |
| `rust_level` | string/int | 否 | 锈蚀等级 | 缺失时允许为空 |
| `observed_magnetism_mt` | float | 是 | 实测剩磁值 | 必须大于 0 |
| `measurement_unit` | string | 是 | 单位 | 必须为 `mT` 或可转换为 `mT` |
| `replicate_count` | int | 否 | 重复测量次数 | 应为正整数 |
| `replicate_mean_mt` | float | 否 | 重复测量均值 | 与主值一致口径 |
| `replicate_sd_mt` | float | 否 | 重复测量标准差 | 不得为负 |
| `instrument_model` | string | 否 | 仪器型号 | 建议记录 |
| `instrument_error_mt` | float | 否 | 仪器误差 | 不得为负 |
| `component_position` | string | 否 | 构件部位 | 如梁、柱、节点等 |

`sample_type` 推荐只允许以下取值：

- `小号铁钉`
- `小号铁夹`
- `普通钢筋`
- `锈蚀钢筋`

---

## 5. weather_series 字段

每一天一行，按日期升序。

| 字段名 | 类型 | 是否必填 | 含义 | 校验规则 |
|---|---|---|---|---|
| `date` | string/date | 是 | 日期 | 必须连续或可识别缺口 |
| `day_index` | int | 否 | 相对第几天 | 若未给出可代码自动生成 |
| `temp_c` | float | 是 | 当日气温 | 合理区间校验 |
| `hum_pct` | float | 是 | 当日相对湿度 | `0-100` |
| `weather_text` | string | 否 | 天气现象文本 | 如晴、小雨 |
| `station_id` | string | 否 | 气象站编号 | 建议记录 |
| `is_imputed` | bool | 否 | 是否插补值 | 默认 `false` |

校验要求：

1. 起始日期应不晚于 `lightning_date`
2. 终止日期应不早于 `measurement_date`
3. `temp_c`、`hum_pct` 缺失过多时应拒绝自动判定

---

## 6. config 字段

| 字段名 | 类型 | 是否必填 | 含义 | 建议默认值 |
|---|---|---|---|---|
| `bootstrap_reps` | int | 否 | bootstrap 次数 | `1000` |
| `ci_level` | float | 否 | 置信水平 | `0.95` |
| `relative_width_threshold` | float | 否 | 区间相对宽度灰区阈值 | `1.0` |
| `min_retention_ratio` | float | 否 | 最小保留率经验阈值 | `0.05` |
| `calibration_floor_ratio` | float | 否 | 校准保守下限比例 | `0.40` |
| `support_prob_accept` | float | 否 | 支持判定概率下限 | `0.975` |
| `support_prob_reject` | float | 否 | 不支持判定概率上限 | `0.025` |
| `threshold_sensitivity_levels` | list[float] | 否 | 阈值敏感性分析倍数 | `[0.9, 1.0, 1.1]` |
| `allow_weather_imputation` | bool | 否 | 是否允许天气插补 | `true` |
| `decision_mode` | string | 否 | 判定模式 | `three_zone` |
| `probability_output` | bool | 否 | 是否输出辅助概率 | `true` |

---

## 7. 推荐输出字段

问题四输出表建议至少包含：

| 字段名 | 含义 |
|---|---|
| `case_id` | 案件编号 |
| `sample_id` | 样品编号 |
| `sample_type` | 样品类型 |
| `delay_days` | 延迟天数 |
| `observed_magnetism_mt` | 实测剩磁 |
| `retention_ratio` | 保留率 `R_s(t)` |
| `dynamic_threshold_mt` | 动态阈值 `Theta_s(t)` |
| `m0_hat_mt` | 反推初值点估计 |
| `m0_hat_lower_mt` | 反推初值下界 |
| `m0_hat_upper_mt` | 反推初值上界 |
| `relative_width` | 区间相对宽度 |
| `decision` | 支持/灰区/不支持 |
| `support_probability` | 辅助概率 |
| `warning_flag` | 是否存在高风险提示 |
| `calibrated_z` | 校准 Z 值 |
| `bootstrap_support_rate` | Bootstrap 支持率 |
| `support_gap_mt` | 反推初值与阈值差值 |

## 8. 推荐输入格式

## 8.1 JSON 结构示例

```json
{
  "case_info": {
    "case_id": "CASE-001",
    "lightning_date": "2026-07-10",
    "measurement_date": "2026-07-25",
    "site_name": "某输电线路铁塔"
  },
  "sample_info": {
    "sample_id": "S-01",
    "sample_type": "普通钢筋",
    "observed_magnetism_mt": 0.92,
    "measurement_unit": "mT",
    "replicate_count": 3,
    "replicate_mean_mt": 0.91,
    "replicate_sd_mt": 0.03
  },
  "weather_series": [
    {
      "date": "2026-07-11",
      "temp_c": 31.2,
      "hum_pct": 78.0,
      "weather_text": "阵雨"
    }
  ],
  "config": {
    "bootstrap_reps": 1000,
    "ci_level": 0.95,
    "relative_width_threshold": 1.0,
    "min_retention_ratio": 0.05
  }
}
```

## 8.2 CSV/Excel 分表输入

如果不用 JSON，建议拆成三张表：

1. `case_info.xlsx`
2. `sample_info.xlsx`
3. `weather_series.xlsx`

优点：

- 便于人工填写
- 便于案件批量处理
- 便于和论文附表一致

## 9. 代码实现建议

当前 `solve_b.py` 是“赛题内闭环脚本”，后续若扩展问题四接口，建议增加以下函数：

### 9.1 输入读取

- `load_case_info(path)`
- `load_sample_info(path)`
- `load_weather_series(path)`

### 9.2 输入校验

- `validate_case_info(case_info)`
- `validate_sample_info(sample_info)`
- `validate_weather_series(weather_series)`

### 9.3 核心计算

- `calc_delay_days(case_info)`
- `calc_retention_ratio(sample_type, delay_days, weather_series)`
- `calc_dynamic_threshold(sample_type, retention_ratio)`
- `backcast_initial_magnetism(observed_magnetism_mt, retention_ratio)`
- `bootstrap_problem4_decision(...)`

### 9.4 最终输出

- `export_problem4_result_csv(...)`
- `export_problem4_summary_xlsx(...)`

## 10. 当前代码与理想接口的差距

当前已经具备：

- 保留率计算
- 反推初值计算
- bootstrap 区间
- 三区域判定

当前还缺：

1. 真实现场输入读入接口
2. 日期和类型校验模块
3. 天气轨迹外部文件读入
4. 仪器误差输入接口
5. 区间相对宽度自动灰区逻辑
6. 批量案件处理接口

---

## 11. 与论文和图表的对应关系

这些字段会直接支撑问题四图表：

- `delay_days`、`relative_width`  
  对应 `fig7_interval_width_delay.svg`

- `sample_type`、`retention_ratio`、`dynamic_threshold_mt`、`decision`  
  对应问题四判定表与流程图说明

- `support_probability`  
  对应正文中的“辅助概率解释”

因此，这套字段设计不是单纯给代码用的，而是问题四论文、表格和图表共用的数据底座。
