# 问题四正式建模方案

## 1. 任务定位

问题四不是重新发明一个新模型，而是在问题一至问题三已完成的基础上，构建一个可执行、可解释、可输出置信结论的雷击判定流程。  
该流程必须严格回到题面四个动作：

1. 数据预处理
2. 衰减预测
3. 动态阈值调整
4. 结果置信度评估

本文档将问题四统一表述为：

> 以样品类型共享衰减函数为核心，用观测时点动态阈值与反推初值两种等价表达完成现场判定，再用 cluster block bootstrap 给出三区域置信结论。

---

## 2. 建模主线

对类型为 `s`、延迟天数为 `t` 的现场样品，设实测剩磁为 `M_obs`，类型共享保留率函数为 `R_s(t | W_{1:t})`，其中 `W_{1:t}` 为从疑似雷击日至观测日的天气轨迹。

问题四继续沿用统一结构：

\[
M_{i,s}(t)=M_{i,s}(0)\cdot R_s(t\mid W_{1:t})
\]

现场判定时不直接观测 `M_{i,s}(0)`，因此要使用下面两种等价表达。

### 2.1 动态阈值表达

将国标初始阈值 `\Theta_s^{GB}` 映射到观测时点，得到：

\[
\Theta_s(t)=\Theta_s^{GB}\cdot R_s(t\mid W_{1:t})
\]

其中：

- 小号铁钉、小号铁夹：`\Theta_s^{GB}=1.0 mT`
- 普通钢筋、锈蚀钢筋：`\Theta_s^{GB}=1.5 mT`

这一定义用于直接查表和现场比较。

### 2.2 反推初值表达

对现场观测值 `M_obs`，定义反推初值：

\[
\hat M_0=\frac{M_{obs}}{\hat R_s(t\mid W_{1:t})}
\]

其含义是：在当前天气轨迹与延迟时长下，把观测值等效推回第 0 天后的估计剩磁。

### 2.3 二者等价关系

\[
\hat M_0\ge \Theta_s^{GB}
\iff
M_{obs}\ge \Theta_s(t)
\]

因此：

- `动态阈值` 适合做 1-90 天表格输出
- `反推初值` 适合做现场解释和置信区间判定

---

## 3. 问题四四步法

## 3.1 第一步：数据预处理

输入现场样品前，必须完成以下检查：

1. 样品类型核验  
   判断是小号铁钉、小号铁夹、普通钢筋还是锈蚀钢筋。

2. 观测时间核验  
   确认疑似雷击日期、取样日期、剩磁测量日期，并统一换算为延迟天数 `t`。

3. 数值质量检查  
   检查剩磁值是否缺失、单位是否统一为 `mT`、是否存在明显录入异常。

4. 天气轨迹匹配  
   收集从疑似雷击日至观测日的逐日温湿度，并与模型天气输入格式对齐。

5. 类型阈值映射  
   根据样品类型自动绑定 `\Theta_s^{GB}` 和对应衰减模型。

如果上述任一步失败，则问题四输出应自动标注为“信息不足，无法完成标准判定”。

---

## 3.2 第二步：衰减预测

已知样品类型 `s`、延迟天数 `t` 与天气轨迹 `W_{1:t}` 后，用问题二最终确定的共享衰减函数计算：

\[
\hat R_s(t\mid W_{1:t})
\]

这是问题四所有后续结果的统一入口。  
当前代码中该量已经通过 `survival(sample_type, day)` 计算，并在问题三中形成了阈值映射表。

---

## 3.3 第三步：动态阈值调整

根据第二步的保留率结果，计算该样品在观测时点的动态阈值：

\[
\Theta_s(t)=\Theta_s^{GB}\cdot \hat R_s(t\mid W_{1:t})
\]

然后将现场实测值 `M_obs` 与 `\Theta_s(t)` 比较：

- 若 `M_obs >= \Theta_s(t)`，则观测值达到该时点的判定要求
- 若 `M_obs < \Theta_s(t)`，则观测值低于该时点的判定要求

这一步只解决“点判定”，还不能表达不确定性。

---

## 3.4 第四步：置信度评估

置信度评估采用 `cluster block bootstrap`。

### Bootstrap 单位

- 以“样品编号”为 cluster
- 每次重抽样保留同一样品的完整时间序列

### Bootstrap 过程

1. 重抽样样品 cluster
2. 重新拟合衰减模型参数
3. 重新计算 `\hat R_s(t)`
4. 重新计算 `\hat M_0`
5. 收集反推初值分布

### 区间估计

对每个现场样品，得到：

\[
[\hat M_0^L,\hat M_0^U]
\]

当前代码已将 bootstrap 重抽样次数提升到 `1000`，正式论文可在此基础上继续检查区间稳定性。

---

## 4. 三区域判定规则

问题四最终结论不使用单一硬阈值，而采用三区域规则：

### 4.1 支持曾遭雷击

若

\[
\hat M_0^L \ge \Theta_s^{GB}
\]

则判定为：

> 支持曾遭雷击

### 4.2 不支持曾遭雷击

若

\[
\hat M_0^U < \Theta_s^{GB}
\]

则判定为：

> 不支持曾遭雷击

### 4.3 灰区 / 证据不足

其余情况均判为：

> 灰区 / 证据不足

这也是当前代码输出 `问题4_三区域判定结果.csv` 的主逻辑。

---

## 5. 辅助概率输出

除三区域主结论外，还可以输出两类辅助量：

1. `Bootstrap支持率`：对 `\hat M_0^{(b)} \ge \Theta_s^{GB}` 的重抽样比例做平滑修正。
2. `校准支持概率`：用 `\hat M_0-\Theta_s^{GB}` 结合 bootstrap 波动、模型残差和保守校准下限计算的正态近似概率。

这两个量只作为解释工具，不替代三区域主判定。

推荐论文中的写法：

- `P >= 0.975`：强支持
- `0.90 <= P < 0.975`：支持
- `P < 0.90` 或区间过宽：灰区

但正式结论仍以三区域结果为准。

---

## 6. 长延迟场景的工程处理

问题四不建议再额外包装“证据寿命”概念，但必须补上长延迟场景的工程规则与阈值敏感性检查。

推荐在代码和论文中加入以下补充判据：

\[
\text{relative\_width}=
\frac{\hat M_0^U-\hat M_0^L}{\hat M_0}
\]

当满足任一条件时，自动偏向“灰区/证据不足”：

1. `relative_width > 1.0`
2. `\hat R_s(t)` 过低，例如小于 `5%`
3. 天气轨迹缺失严重或样品类型无法可靠识别

当前代码中已完成三区域判定、bootstrap 区间与区间相对宽度输出；“区间相对宽度触发灰区”建议作为正式补充规则写入正文。

另外建议补充 `±15%` 阈值敏感性分析表，并汇总成判定稳定性表，用于展示结论对国标阈值扰动是否稳定。

## 9. 论文口径建议

问题四正文建议统一写成：

> 对现场样品，先根据样品类型、延迟天数和天气轨迹计算共享保留率，再将国标静态阈值映射为观测时点动态判定线，并等价地反推初始剩磁；随后通过 cluster block bootstrap 获得反推初值区间，最终给出“支持 - 灰区 - 不支持”的三区域工程判定结论。

必须避免的说法：

- “问题四证明了是否雷击”
- “问题四给出确定性结论”
- “动态阈值就是新的国标阈值”

更稳妥的说法是：

- “工程判定”
- “证据支持程度”
- “不确定性控制”
- “灰区复检建议”
